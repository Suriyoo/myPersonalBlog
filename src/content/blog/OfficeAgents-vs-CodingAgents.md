有人认为，Agent 本质上都是通用的，没有必要专门区分办公 Agent 和编程 Agent。但我认为，两者确实有明显区别。最重要的区别在于：使用者是否需要具备开发能力。

<p class="translation">Some people argue that all AI agents should be general-purpose, making the distinction between office agents and coding agents unnecessary. I see it differently. The key difference is whether users need a technical background to use them.</p>

一个真正通用的 Agent，应该尽可能降低使用门槛，让不懂编程的人也能轻松使用。

<p class="translation">A truly general-purpose agent should require as little prior knowledge as possible. It should be accessible even to people with no programming experience.</p>

<div class="section-heading">
<h2>为什么编程 Agent 不适合所有人？</h2>
<p class="section-translation">Why Aren't Coding Agents Suitable for Everyone?</p>
</div>

编程 Agent 通常围绕开发者的工作方式设计。例如，开发者可以通过 Git 管理代码和团队协作，也习惯直接操作本地文件、修改代码和配置环境。

<p class="translation">Coding agents are generally designed around developers' workflows. For example, developers use Git for version control and collaboration. They are also comfortable working with local files, editing code, and configuring development environments.</p>

这些对开发者来说很自然，但对普通办公人员来说却很复杂。学习 Git、管理代码和配置开发环境，都可能成为使用障碍。

<p class="translation">These practices are natural for developers but can be difficult for ordinary office workers. Learning Git, managing code, and setting up development environments can all become barriers.</p>

更重要的是，普通用户并不关心 Agent 如何编写代码。他们真正需要的是最终结果，比如文档、表格和网页。对他们来说，代码只是完成任务的中间过程，而不是需要交付或维护的产品。

<p class="translation">More importantly, most office workers don't care about how an agent writes code. They care about the final results, such as documents, spreadsheets, and websites. For them, code is simply an intermediate step in completing a task, not something they need to deliver or maintain.</p>

<div class="section-heading">
<h2>办公 Agent 应该如何设计？</h2>
<p class="section-translation">How Should Office Agents Be Designed?</p>
</div>

既然普通用户不需要接触代码，那么 Agent 就应该负责管理整个程序和执行环境。

<p class="translation">If users don't need to work with code, the agent should take full responsibility for managing the code and its execution environment.</p>

用户只需要提出需求、检查结果和编辑最终产物，不必了解代码如何运行。

<p class="translation">Users should only need to describe what they want, review the results, and edit the final output. They shouldn't need to understand how the code works.</p>

这也意味着，程序最好运行在云端的隔离环境中，而不是直接运行在用户自己的电脑上。

<p class="translation">This suggests that programs should run in isolated cloud environments rather than directly on users' computers.</p>

云端设计还能带来更多优势：

<p class="translation">A cloud-first design also offers several advantages:</p>

不需要学习 Git，也能方便地与同事协作。

<p class="translation">Teams can collaborate without learning Git.</p>

不需要管理代码和开发环境。

<p class="translation">Users don't need to manage code or development environments.</p>

可以降低程序对本地电脑和企业环境造成的风险。

<p class="translation">Risks to local computers and corporate systems can be reduced.</p>

可以在不同设备之间切换任务。

<p class="translation">Tasks can move seamlessly between different devices.</p>

即使电脑关机，云端任务仍然可以继续运行。

<p class="translation">Cloud-based tasks can continue running even when a user's computer is turned off.</p>

Manus 就是这种设计思路的一个代表。

<p class="translation">Manus is one example of this approach.</p>

<div class="section-heading">
<h2>Agent 的未来不应该只由技术驱动</h2>
<p class="section-translation">The Future of Agents Should Not Be Driven by Technology Alone</p>
</div>

目前，市场上有不少人更关注 OpenClaw 这类单机优先的 Agent 产品，而低估了 Manus 这类云端办公 Agent 的价值。

<p class="translation">Much of the current attention is focused on single-machine-first agent products such as OpenClaw, while the value of cloud-based office agents like Manus may be underestimated.</p>

这可能与技术人员的思维方式有关：他们更容易从技术实现的角度评价产品，而不是从普通用户的实际需求出发。

<p class="translation">This may reflect how some technical professionals evaluate products. They tend to focus on technical implementation rather than the actual needs of everyday users.</p>

但一个产品是否优秀，不应该只看它使用了什么技术，更应该看它能否真正解决用户的问题。

<p class="translation">However, a product should not be judged only by its technology. What matters more is whether it genuinely solves users' problems.</p>

市场上也出现了 Raft 等更强调团队协作和企业管理的 Agent 工作空间产品。这些产品正在探索如何让 Agent 更自然地融入企业的日常工作。

<p class="translation">Other products, such as Raft, are also exploring agent workspaces with stronger collaboration and enterprise management capabilities. They aim to make agents a more natural part of everyday business operations.</p>

<div class="section-heading">
<h2>产品质量比市场热度更重要</h2>
<p class="section-translation">Product Quality Matters More Than Market Hype</p>
</div>

在一个新兴市场中，用户和企业的选择往往受到品牌知名度、市场热度和焦虑情绪的影响，而不完全取决于产品质量。

<p class="translation">In emerging markets, purchasing decisions are often influenced by brand recognition, market trends, and fear of missing out rather than product quality alone.</p>

因此，市场份额暂时不一定能反映产品的真实价值。

<p class="translation">As a result, market share does not always reflect a product's true value.</p>

但从长期来看，选择高质量 Agent 工具的团队，更有可能获得实际收益；盲目跟风的团队，则可能承担不必要的成本。

<p class="translation">In the long run, teams that choose high-quality agent tools are more likely to gain real benefits, while those that blindly follow trends may end up paying unnecessary costs.</p>

这也给创业公司带来了机会。只要真正理解用户需求，并做好产品体验，即使面对大公司，也依然有机会脱颖而出。

<p class="translation">This also creates opportunities for startups. Companies that truly understand user needs and focus on product experience can still stand out, even when competing with much larger businesses.</p>

真正优秀的 Agent，不只是技术能力强，更重要的是让用户能够轻松完成工作。

<p class="translation">A great agent is not just about powerful technology. It is about helping people get things done with less effort.</p>
